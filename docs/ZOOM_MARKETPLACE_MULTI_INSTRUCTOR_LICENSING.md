# Zoom Marketplace والتراخيص — التوسع لعدة مدرسين

**المنتج:** AviatorPass (ATPL PASS)  
**تاريخ الوثيقة:** 30 أكتوبر 2026 (Asia/Dubai)  
**Production tip:** SHA `ce29a4a` — الخيار A (Meeting SDK + مضيف مركزي S2S)

## 1) الوضع الحالي (Option A)

| مكوّن                                                 | الدور                                        | الحالة                                          |
| ----------------------------------------------------- | -------------------------------------------- | ----------------------------------------------- |
| Meeting SDK Classroom (`VGTQ`)                        | JWT للانضمام المضمّن داخل `/join`            | معمّد على Production                            |
| Server-to-Server CEO (`uX3Q` / `ceo@aviatorpass.com`) | إنشاء الاجتماعات + `start_url` لـ ZAK المضيف | معمّد                                           |
| Instructor OAuth (`Z0xA`)                             | استضافة شخصية اختيارية لكل مدرس              | كود موجود؛ **غير مطلوب** للتشغيل المركزي الحالي |
| Zoom Marketplace Submit                               | إدراج التطبيق للمراجعة العامة                | **لم يُنفَّذ** — موافقة مالك فقط                |

التشغيل اليومي لا يعتمد على موافقة Marketplace. مسار Marketplace منفصل عن إغلاق تسليم العميل.

## 2) حد الترخيص المتزامن

- مستخدم Zoom مرخّص واحد يستضيف عادة **اجتماعًا حيًّا متزامنًا واحدًا**.
- تعدد الصفوف الحية في نفس النافذة الزمنية على نفس حساب CEO قد يفشل أو يظهر **Error 3000**.
- AviatorPass يمنع:
  - تداخل جدول **نفس المدرس** (`detectScheduleConflicts`).
  - إسناد اجتماع جديد لمضيف Zoom مشغول بنافذة صف AviatorPass أخرى (`chooseZoomHostUser` → HTTP 409).
- clear-live: جرد + إنهاء أشباح محلية معروفة / أرقام صريحة فقط — **لا** إنهاء جماعي لاجتماعات غير معروفة.

## 3) التوسع إلى عدة مدرسين متزامنين

| خيار                                         | ماذا يلزم                                                                         | إعادة تطوير منصة؟                        |
| -------------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------- |
| **أ — جدولة متداخلة**                        | صفوف حية غير متزامنة على المضيف المركزي الحالي                                    | لا                                       |
| **ب — مضيفون Zoom إضافيون على نفس حساب S2S** | إضافة مستخدمين مرخّصين في حساب Zoom للمنصة؛ S2S يختار مضيفًا حرًا عند التوفر      | لا (إعداد Zoom + ترخيص)                  |
| **ج — Instructor OAuth لكل مدرس**            | تفعيل مسار `Z0xA` وربط كل مدرس بحساب Zoom خاص                                     | إعداد + تشغيل؛ ليس إعادة تصميم Classroom |
| **د — Submit Marketplace / scopes جديدة**    | موافقة مالك صريحة؛ خطة `meeting:read:list_meetings` منفصلة لتحسين وضوح clear-live | بوابة Zoom فقط عند الموافقة              |

**التوصية للتسليم الحالي:** الخيار أ للتشغيل الآمن؛ الخيار ب عند حاجة سعة متزامنة دون تغيير بنية Classroom.

## 4) Scope مقترح (اختياري — خارج إغلاق العميل)

انظر `docs/ZOOM_S2S_MEETING_READ_SCOPE_PLAN.md`:

- الهدف: `meeting:read:list_meetings` (أو `:admin`) على تطبيق S2S فقط.
- الفائدة: `liveListReadable: true` لجرد Error 3000 بأمان أكبر.
- **لا يُطبَّق دون موافقة المالك.** لا يمس VGTQ / Z0xA.

## 5) ما لا يُفعل دون موافقة

- Submit على Marketplace
- إنشاء تطبيق Zoom جديد أو تدوير Client ID/Secret
- OBF / `user:read:token`
- إنهاء جماعي لاجتماعات Zoom الحية غير المعروفة
